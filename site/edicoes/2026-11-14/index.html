memory and contexttest

DISCERN: Preserve at Write, Resolve at Read for Persistent LLM-Agent Memory

DISCERN replaces conventional RAG-style memory retrieval (embedding search over merged or overwritten memory entries) with a strictly additive bi-temporal provenance graph written without merging entities or dropping superseded values, plus a zero-LLM tool surface that an agentic loop navigates to commit one of four gated terminal actions, including abstention. The cost is implementation complexity: a custom graph schema, write-time provenance instrumentation, and a read-time navigation loop with more orchestration steps and thus higher per-query latency than a single vector lookup, though it runs within a single-GPU or API-only budget since the tool surface itself uses no LLM calls. It can fail if the write-time extraction of entities and time-states is noisy, since errors accumulate in an append-only graph that is never corrected, and the headline gains are demonstrated on a 310-query synthetic benchmark, so real-world entity-resolution and abstention benefits remain unvalidated.

Faithful in Steps: Improving Generalization and Citation in RAG via Query Decomposition

The technique replaces single-pass attributed RAG (RAGQ), where the model retrieves and cites contexts directly for the full question, with a pipeline that decomposes the question into atomic subquestions to resolve implicit entities, then uses a reranker to prune distractor contexts and reduce over-citation. Read Once, Answer Many: Parallel Prompting for Shared-Context LLM Inference

The method replaces prefix caching plus per-question decoding, in which every decode step re-reads the shared document's KV cache once per question, by decoding P questions as P independent streams of a single request with a stream-id attention mask inside the kernel, so the document is read once per step for all streams. The cost is a forked SGLang (about 80 lines across three files plus a small engine package), fixed-shape decode steps required for CUDA-graph capture, and applicability only to workloads with many independent questions over one long document. It can fail when the agent does not actually report its satisficing choices, when the checking step is biased toward the same rationalizations the paper identifies, and gains may not transfer to task types or backbones beyond those evaluated.

Rasoi: Visual Diffs for Evaluating Structural Changes Made by Coding Agents

Rasoi replaces manual inspection of raw textual diffs after coding-agent edits with visual diffs that show which architectural elements and relationships were added, modified, or removed across abstraction levels. It costs the effort of building or adopting an architecture-extraction and visualization layer on top of existing diff tooling; it is a design probe from a 12-developer qualitative study, not a shipped product, so adopting it means implementing the capability in-house.
