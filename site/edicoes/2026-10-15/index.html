The COUNT: Counting N-grams Unlocks Scaling on Host Memory and Training-Free Adaptation

COUNT replaces learned n-gram embedding tables (trained from scratch on GPU) with precomputed corpus n-gram counts stored in host memory, which weight the LM's own unembedding rows to form embeddings with no additional learned parameters. It costs host RAM for the count table, preprocessing to build it, and an added embedding lookup per token; the benefit only materializes if the backbone is pretrained with COUNT as an input. It can fail for the reader because the gains are demonstrated only for models pretrained from scratch with the method, and no compatible pretrained checkpoint may exist; count tables can also be stale or mismatched to the target domain, degrading the training-free adaptation.

Replaces one-shot KV-cache eviction/compression heuristics with a per-document learned compact cache, optimized via test-time training using generic prompts while model weights stay frozen. ActionOPD: Distilling Decisions, Not Tokens

ActionOPD replaces offline imitation and token-level on-policy distillation with action-level on-policy distillation, rewarding student actions by semantic agreement with sampled teacher actions, so teacher token probabilities and shared tokenization are no longer required. It costs an on-policy RL training loop with sampling from both student and teacher at each state, which is substantially more compute- and orchestration-intensive than offline supervised fine-tuning, though the teacher can be a black-box API. It can fail if the sampled teacher actions are unrepresentative or the semantic-agreement reward is noisy, and the gains are demonstrated only on curated tool-use tasks, so transfer to other agent workloads is unverified.

Encoder Awakening via Adapters: Effective Domain-Adaptive Fine-tuning of Speech-LLMs

It replaces direct joint fine-tuning of a Speech-LLM (or LoRA-only LLM adaptation) with a two-stage procedure: first train lightweight adapters inserted into each frozen speech-encoder layer, then jointly fine-tune the whole model with LoRA on the LLM. AdaRSI: On-Demand Recursive Self-Improvement for Embodied Agents

AdaRSI replaces indiscriminate fine-tuning of every failing sub-step (or harness-only refinement of a frozen executor) with a failure-attribution loop: a coding agent retries failing sub-steps from saved states, distinguishes harness errors from capability gaps, and fine-tunes only the sub-steps that remain unreliable using self-collected demonstrations. The cost is substantial supporting infrastructure: a checkpointable simulator environment, a coding agent to manage the loop, state saving and replay, and repeated fine-tuning runs of a VLA executor, which is feasible on a single GPU only for modest models. Failure modes include misattribution of harness versus capability errors, low absolute success (13.8% on unseen composites) that limits production readiness, distribution shift from self-collected demonstrations, and dependence on a resettable simulation that most real-world deployments lack.

LAGO: Language Agents with Reusable Growing Options

LAGO replaces a single monolithic tool-use loop, in which one agent must decompose, execute, and verify within one trajectory, with a meta-agent that retrieves or spawns specialized sub-agents stored as reusable options in a persistent library that grows across tasks without weight updates. The cost is orchestration complexity plus additional inference calls for meta-agent dispatch, verification, and admission of new options, since a frozen model is used in both roles and no training is required. It can fail when decomposition quality is poor, when the library accumulates mislabeled or non-transferable options, or when gains do not replicate across models and task distributions, as the ablation shows component contributions are task- and model-dependent.

The method replaces convention- or grid-search-based selection of attention head count with a label-free intrinsic-dimension estimate from a nested-dropout VAE, avoiding a hyperparameter sweep. Why Generate a Click? Plug-in Decision Heads for Web Agents

The method replaces text-based action decoding (generating tokens like click(12)) with lightweight classification heads that read action type, target element, and text-option choices directly from the frozen generator's hidden states, falling back to full decoding from the same forward pass's KV cache when head confidence is low. Costs include training the heads on web-step data (the paper used 213k steps), an additional confidence-threshold hyperparameter per deployment, and up to 2 points of step-success regression on some benchmarks (GUIAct, MiniWoB++) under loose thresholds. Failures after adoption can come from miscalibrated confidence on out-of-distribution websites, from UI layouts whose element structure differs from training data, and from degradation of the generator itself if heads are trained jointly rather than on frozen weights (up to 4.9 points of generator step-success loss).

Sparse Autoencoders for Mechanistic Interpretability in NLP: A Critical Survey of Recoverability, Interpretability, and Utility

The survey covers sparse autoencoders, which replace dense, polysemantic hidden activations with sparse feature dictionaries intended to be individually interpretable; it does not propose a new method but critically reviews 138 studies. Adoption costs include training a separate autoencoder per model layer, added storage and inference overhead, and evaluation complexity, all within a literature whose results the authors show depend heavily on design assumptions and evaluation settings. Failure modes documented in the survey include features that do not faithfully reconstruct activations, non-robust semantic interpretability, and weak or inconsistent evidence of behavioral utility in downstream interventions.

P2Patch: Exploit-Guided Vulnerability Repair

P2Patch replaces single-pass vulnerability repair, where a patch is validated only against the evidence used to construct it, with an adversarial loop in which an exploitation agent generates new same-vulnerability exploits against each patched program and the final patch must block all accumulated proofs of vulnerability. The cost is multiple agent iterations per finding (exploitation plus patching per round) on third-party APIs, increasing token spend and end-to-end latency per CVE, plus infrastructure to run PoVs and maintain separate held-out evaluation oracles. It can fail when the exploitation agent cannot produce a working PoV for a vulnerability class, when accumulated repair requirements overfit to the generated exploits rather than the underlying flaw, and because absolute coverage gains are modest, the added cost may not pay off on low-severity findings.

The COUNT: Counting N-grams Unlocks Scaling on Host Memory and Training-Free Adaptation

memory and context · test · 1 of 2 implementations is independent

COUNT replaces learned n-gram embedding tables (trained from scratch on GPU) with precomputed corpus n-gram counts stored in host memory, which weight the LM's own unembedding rows to form embeddings with no additional learned parameters. It costs host RAM for the count table, preprocessing to build it, and an added embedding lookup per token; the benefit only materializes if the backbone is pretrained with COUNT as an input. It can fail for the reader because the gains are demonstrated only for models pretrained from scratch with the method, and no compatible pretrained checkpoint may exist; count tables can also be stale or mismatched to the target domain, degrading the training-free adaptation.
