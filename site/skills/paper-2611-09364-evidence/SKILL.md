## Reported claims

- The method replaces unconstrained LLM-to-MCP tool use with a pipeline that derives atomic goals from natural-language intent, generates runtime-checkable LTL-style specifications, grounds them to WoT Thing Description affordances, and verifies candidate actions against SMT-backed safety constraints before execution. The cost is added system complexity and latency: the pipeline requires an LTL generation step, a grounding step, and an SMT solver in the execution loop, plus engineering effort to maintain the specification and constraint models. Failure modes include incorrect or incomplete LTL specifications generated by the LLM, grounding errors when affordances are ambiguous, and SMT models that are over-permissive or over-restrictive, which can respectively admit unsafe actions or block legitimate ones. (inferred)
- Maintains 100% required action accuracy and 100% MCP Execution Similarity on all but one task (92%), versus a baseline whose MCP ES falls to 13% on multi-device, event-triggered, and ordered tasks. (inferred)
