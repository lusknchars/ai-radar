#### 1. Retrieval-induced tree navigation for RAG

RIT-RAG replaces flat chunk retrieval and single-document structure navigation (e.g., PageIndex) with a hybrid: broad chunk retrieval induces sub-trees from per-document table-of-contents/sitemap trees, which an LLM agent then navigates and selectively reads. Costs include an offline tree-construction pipeline per document, additional LLM agent calls for navigation, node reading, and query reformulation (higher latency and API spend per query than vanilla RAG), plus engineering complexity in maintaining document-structure extraction. Failure modes include documents lacking reliable TOCs or sitemaps, retrieval proposing poor starting positions that mislead the induced sub-tree, and agent navigation errors accumulating over multiple steps, which may not justify the gains on small or weakly structured corpora.

#### 2. Three-stage domain-adapted RAG for regulatory QA

Replaces off-the-shelf dense or BM25 retrieval and prompted compact LLMs with a LegalBERT retriever tuned via entailment reformulation, contrastive in-batch negatives, and BM25 score fusion, plus optional RAFT-LoRA on a quantized 2B-12B generator, all feasible on a single 24 GB GPU. Costs include three retriever fine-tuning stages, labeled domain data for entailment and contrastive tuning, hybrid-fusion serving complexity, and per-domain RAFT adaptation. It can fail on domain transfer (no generalization to Australian case law), and RePASs gains do not demonstrate grounding: a closed-book model scored within 0.011 RePASs while citing nothing and misstating obligations, so a dedicated grounding evaluation must be built before production trust.

#### 3. Cut-point record-and-replay regression tests for agents

The method replaces ad-hoc manual reproduction of agent failures and full live re-runs with recorded envelopes at model and tool boundaries, replayed selectively so that only the code under test executes live, turning each incident into a deterministic CI regression test. The cost is instrumentation of all non-deterministic boundaries, storage of immutable run records, and 23 microseconds of recording overhead per crossing, plus the engineering effort to maintain replay-compatible boundaries as the agent evolves. It can fail when trajectories drift so that the recorded suffix no longer matches the new code's live prefix, when tools or models change their interfaces, and because the evidence base is only six incidents with simulated model boundaries, leaving real-model fidelity unproven.

The cost is infrastructure and operational effort to self-host the applications and run isolated parallel evaluations, plus dependence on API access for the strongest agents; it measures agent quality rather than improving it. It can fail to transfer if the reader's production tasks differ from the benchmark's application categories, if self-hosting drifts from the released configurations, or if API model updates change agent behavior between evaluations. - **Auditable evaluation and intervention loop for agents** — Replaces ad-hoc prompt tuning and leaderboard-score trust with repeated-run stability measurement, trace-based fault attribution by owning layer, and a gated optimization loop that keeps changes only if they beat a pre-registered threshold. Costs include running multiple evaluation passes to quantify variance, maintaining a frozen failure taxonomy, and blind human or multi-model trace review for diagnosis validation. Can fail if run-to-run variance is underestimated on small question sets, leading to false confidence in gains that fall within noise, as the paper itself demonstrates with its accuracy objective. - **Benchmarking LLM agents via taxonomy-based multi-label reformulation** — MineralExp replaces unstructured human judgment of open-ended experimental designs with a 19-type taxonomy that converts experimental design into deterministic multi-label classification, supplemented by an LLM-as-a-Judge metric.
