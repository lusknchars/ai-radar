#### 1. Backward revision of textual agent memory

It replaces forward-only memory/reflection harnesses (and replay- or validation-based harness optimization) with a strictly online scheme that, after each streamed instance, revises previously retrieved reflections using the resulting trajectory as backward feedback. The cost is extra inference calls per instance for revision, added harness complexity, and growth/maintenance of a textual state, all feasible on a single 24 GB GPU or via APIs. It can fail if revisions propagate errors from noisy trajectories, if the workload lacks distribution shift or long interaction streams where continual adaptation matters, or if revision quality depends on backbone strength not matched in the reader's deployment.

#### 2. Unified knowledge distillation toolkit (SilverSpoon-KD)

SilverSpoon-KD replaces ad hoc or narrow distillation implementations with a single PyTorch API covering homogeneous, heterogeneous, quantization, and blockwise distillation across vision and language workloads. The cost is added toolkit dependency and integration complexity, plus the compute required to run teacher-student training, which on a single 24 GB GPU may require the blockwise mode or small teachers. Failure modes include student quality regressions relative to the teacher on domain-specific tasks, mismatched architectures limiting applicable distillation methods, and toolkit maturity risks typical of new open-source releases.

#### 3. Parallel contextual correction for diffusion-based speculative drafts

DCOCO replaces the top-1 commitment of parallel diffusion-based drafters (e.g., DFlash) by retaining multiple candidate tokens per draft position and scoring their contextual compatibility across adjacent positions in parallel, restoring intra-block dependencies without sequential drafting. It costs an additional lightweight correction stage per draft block, extra candidate storage, and integration into a diffusion-drafter serving stack, and it is not drop-in for conventional autoregressive speculative decoding. It can fail when the verifier or drafter backbone differs from the evaluated configurations, when the correction overhead erodes gains at low batch sizes, or when sequential correctors under load are the actual bottleneck it claims to avoid.

#### 3. Candidate filtering and consensus gating for agent execution

CANDID replaces textual self-reflection and unguarded action loops in computer-use agents with structural execution controls: parallel candidate sampling filtered by a loop-recovery mechanism at failure-prone steps, plus a unanimous-consensus gate before the agent may declare DONE. The cost is additional inference calls at sparse intervention points for candidate generation, plus the engineering complexity of detecting critical junctions and maintaining the gating logic, though the paper claims minimal execution overhead. Failure modes include the loop filter rejecting correct repetitive behaviors, the conservative DONE gate causing agents to continue past task completion (wasting budget or corrupting state), and reliance on a verifier or consensus procedure whose errors become systematic since it controls termination.

It can fail because deterministic rules catch only about half of cheats, judge effectiveness was validated mainly on Sonnet-generated behavior, models may route around specific prompt wording, and a capable agent that can alter the judge-visible transcript could hide tool calls unless the signed record is the sole evidence source. (avaliacao_de_agente · adotar) arxiv.org/abs/2611.23335
- **Sandboxed coding agents with provenance ladder** — The method replaces ad-hoc, unsandboxed use of AI coding agents with Docker-sequestered agent execution, file-change monitoring via a GUI, and a six-level PROOF scale classifying results by provenance, reproducibility, openness, oversight, and falsifiability, with tooling support up to Level 3 (reproducible). Costs include container setup and maintenance, GUI-based workflow overhead, prompt-transcript and change-history bookkeeping, and the engineering effort to make projects reproducible; the abstract reports no measured latency, memory, or quality impact. Failure modes include incomplete sandboxing letting agent mistakes damage the host environment, false confidence from low PROOF levels, validation burden remaining on the researcher, and higher levels requiring independent regeneration and cryptographic attestation that a small team may not be able to sustain. (agentes_de_codigo · testar) arxiv.org/abs/2611.23334
- **Agent trajectory analysis as QA evidence** — The proposal would replace reliance on final code and passing tests as sole QA evidence with structured analysis of agent execution trajectories to prioritize consequential decisions for human scrutiny. The cost is instrumentation to capture trajectories, new analysis tooling, and additional reviewer effort, with no quantified benefit established. It can fail because trajectories do not establish that decisions were justified or corrective changes effective, and the added scrutiny may not outperform simpler existing QA approaches. (avaliacao_de_agente · observar) arxiv.org/abs/2611.22323
- **Physical-world verification pipeline for agent-generated code** — The paper proposes treating physical trials, simulators, learned judges, and formal checks as the 'test suite' for robot and lab code, replacing ad hoc or absent verification of programs written by coding agents for physical actuators. The cost is the expense and potential unreliability of physical evidence: real-world trials are costly and slow, while cheaper substitutes (simulators, learned judges, traces) can be wrong or gameable under search, and building a physical continuous-integration pipeline requires ongoing maintenance of skill libraries and evaluation infrastructure. What can fail is verification drift: learned or simulated judges diverge from real-world behavior, so programs validated cheaply may fail on hardware or violate safety constraints that task success alone does not capture. (avaliacao_de_agente · observar) arxiv.org/abs/2611.22291
- **Multi-agent memory inconsistency benchmark and evidence-flow profiler** — This is a benchmark and evidence-flow profiler for diagnosing memory inconsistency in multi-agent LLM systems; it replaces informal assumptions that delegating retrieval to workers preserves the lead agent's ability to detect factual conflicts. It costs nothing in model capacity but adds evaluation instrumentation and logging of worker-to-lead evidence flow, and the operational implication is that handoff design or claim co-location must be engineered explicitly. Adoption can fail because the findings are measured on Harvey LAB document-review tasks with three models at matched generation spend, so the specific rates may not transfer to other domains, and fixing handoffs does not guarantee detection improves in a different pipeline. (avaliacao_de_agente · testar) arxiv.org/abs/2611.22245
- **Cost-aware context management evaluation for coding agents** — This is a measurement framework for context-management policies (adding retrieved code, removing stale tool observations) in coding agents, replacing ad hoc prompt engineering decisions and naive token counting with cost accounting that separates uncached input, cached input, and output tokens. It costs engineering effort to instrument per-category token usage and to control for shared cached prefixes across concurrent runs, and it adds no new model or infrastructure dependency. It can fail if applied as a blanket conclusion: the negative results depend on a specific cache price ratio (one tenth of uncached) and on specific benchmarks, so a policy that loses money in this study may still pay off under different provider pricing, cache behavior, or task distributions, and shorter prompts can backfire by inducing more agent steps. It can fail through misclassification of gray-zone queries, over-redirection that degrades pedagogical utility, or audit misses that pass unsafe outputs, and its benefits are unverified outside the paper's own benchmarks.
