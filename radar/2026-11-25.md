#### 1. Explicit skill preselection over implicit routing

Explicit preselection of relevant skills before agent execution replaces implicit routing, in which the agent scans full skill metadata and decides what to load during the task. It costs an additional selection step with its own latency and coverage trade-offs, and requires a mechanism (retriever or selector model) to pick candidate skills from the library. It can fail when the preselector misses the golden skill, since the agent then has no opportunity to recover it, and gains shrink when libraries are small enough that implicit routing has not yet collapsed.

#### 2. Derived-reference generation for tool-call judges

DeRef replaces giving the judge raw (possibly truncated or reference-free) conversation history by having a separate model read the full history without seeing the candidate argument and write an explicit reference stating what the value should be. It costs one additional model inference per judged argument, adding latency, API or GPU cost, and a new pipeline component. It can fail when the reference-writing model itself misderives the intended value, since judges are shown to follow the visible reference even when it is incorrect, so a wrong reference can systematically flip verdicts.

#### 3. Factorized Context Attention (native grid probing)

Factorized Context Attention replaces grid probing's repeated per-span re-encoding with a native block-sparse attention pass that encodes the input once into a shared KV cache and reads all local and strided spans in one batched forward. It costs a custom attention implementation with masking plus a stair position schedule, rather than any training or extra parameters. It can fail where the block-sparse pattern is unsupported by the reader's inference stack, where spans straddle the trained position range despite the schedule, or where tasks need dense cross-span interactions that strided probing misses.

#### 2. Trained deep search agents via SFT-KTO-CM-GSPO

Failure modes include catastrophic forgetting of general coding ability if the scaffold-removed-to-skill-native mixture ratio is wrong, loss of task-specific skill invocation, and internalized procedures becoming stale or inapplicable on out-of-distribution tasks. (destilacao · testar) arxiv.org/abs/2611.32246
- **Boundary-aware handoff training for agent-orchestrated robot policies** — Boundary-Aware Policy Learning replaces ad hoc agent-to-policy invocation, in which a visuomotor policy is called from states outside its reliable start region, with explicit shaping of a 'handoff boundary' via fine-tuning on diverse-start contact segments plus retraining on curated successful rollouts. The cost is a two-stage policy training pipeline on robot demonstration data (RoboTwin 2.0, RoboDojo) and maintenance of a handoff protocol the agent must follow, plus compute for iterative self-improvement retraining. The method can fail when deployment tasks or embodiments differ from training distributions, and its gains are validated only in simulation benchmarks rather than on physical hardware. (orquestracao_multiagente · nao_aplica) arxiv.org/abs/2611.32238
- **Deny-preserving, author-attributed permission policy updates** — The technique replaces unchecked acceptance of permission-prompt answers and policy updates from plugins and remote services with an enforced update step that either permits only updates preserving every currently denied call, or attributes each rule to its author and lets parties remove only their own restrictions. It costs little in memory or latency but adds enforcement logic at the shared policy-update path and constrains legitimate delegation, since without authorship records no remote party can safely relax any rule. What can fail after adoption is incomplete coverage: relays that bypass the shared update step, runtimes lacking authorship records, or agents outside the thirteen audited designs may still permit deny-rule deletion, and the vendor's indistinguishable logging of remote versus operator edits limits forensic detection. (seguranca_e_guardrails · adotar) arxiv.org/abs/2611.32195
- **Authenticated user-message provenance for authorizers across compaction** — The technique replaces letting the authorizer derive its policy from the compactor's model-written summary (which conflates user text with injected content) with deriving policy only from user messages authenticated on arrival and carried verbatim across the compaction boundary, while the agent still reads the summary for context. It costs engineering effort to thread authenticated user text through the agent framework and gives the attacker a denial-of-policy option: they can block policy derivation but cannot shape it, and compaction quality for the agent itself is unchanged. It can fail where the agent framework does not expose a trust boundary between user turns and summaries, where legitimate user intent spans content that arrived as tool output rather than user text, or where authorization of requests beyond the frozen/derived per-request policy is needed. (seguranca_e_guardrails · adotar) arxiv.org/abs/2611.32194
- **Graph-based experience risk assessment and repair** — ExpGuard replaces ad hoc or absent vetting of retrieved agent experiences with a task-conditioned heterogeneous graph risk predictor, counterfactual-replay risk labeling, and online repair of flagged experiences before they enter the agent's context. The costs are additional graph construction and inference at retrieval time, a matched counterfactual replay pipeline requiring checkpointed task environments for training, and ongoing maintenance of the risk model. It can fail when replay environments or checkpoints are unavailable, when risk labels misclassify subtle attacks, or when the repair step degrades legitimate experience utility and hurts task completion. (seguranca_e_guardrails · testar) arxiv.org/abs/2611.32085
- **Online environment repair for RL coding agents** — Online environment repair replaces reward-penalty, rollout-filtering, and static pre-training verifier hardening by asynchronously patching exploited test harnesses during RL training while leaving triggering rewards unchanged. It costs an asynchronous pipeline of candidate-repair generation (execution invariants, differential fuzzing) plus three automated validation gates per repair, adding training-time infrastructure complexity rather than inference latency or memory. It can fail if validation gates pass an incomplete patch, if repair generation misses exploit classes outside its invariants and fuzzing reach, or if the reader lacks the RL training loop it presupposes, making it inapplicable to inference-only or supervised fine-tuning workflows. (agentes_de_codigo · observar) arxiv.org/abs/2611.32037
