#### 1. KV-cache compression via test-time training

Replaces one-shot KV-cache eviction/compression heuristics with a per-document learned compact cache, optimized via test-time training using generic prompts while model weights stay frozen. Costs a per-document training pass at inference time (extra latency and compute before serving, plus engineering complexity for the two-stage distillation procedure), though memory during generation drops by the compression factor. Can fail when the per-document training cost exceeds the cache savings (short documents, single-query workloads), when generic prompts fail to cover the information later questions require, or when serving infrastructure cannot amortize the per-document training across many queries.

#### 2. Encoder adapter pre-training plus LoRA joint fine-tuning for ASR

It replaces direct joint fine-tuning of a Speech-LLM (or LoRA-only LLM adaptation) with a two-stage procedure: first train lightweight adapters inserted into each frozen speech-encoder layer, then jointly fine-tune the whole model with LoRA on the LLM. The cost is an extra training stage, modest additional adapter parameters in the encoder, and a more complex pipeline than a single LoRA pass; it presumes an existing Speech-LLM checkpoint and target-domain labeled audio. It can fail if the target domain is not acoustic-shifted (e.g., the gap is lexical or semantic rather than child/dialectal acoustics), if very limited target data overfits the encoder adapters, or if the base model is not an encoder-projector-LLM ASR stack, making the method inapplicable.

#### 1. Host-resident count-weighted n-gram embeddings (COUNT)

COUNT replaces learned n-gram embedding tables (trained from scratch on GPU) with precomputed corpus n-gram counts stored in host memory, which weight the LM's own unembedding rows to form embeddings with no additional learned parameters. It costs host RAM for the count table, preprocessing to build it, and an added embedding lookup per token; the benefit only materializes if the backbone is pretrained with COUNT as an input. It can fail for the reader because the gains are demonstrated only for models pretrained from scratch with the method, and no compatible pretrained checkpoint may exist; count tables can also be stale or mismatched to the target domain, degrading the training-free adaptation.

#### 2. Action-level on-policy distillation for agents

ActionOPD replaces offline imitation and token-level on-policy distillation with action-level on-policy distillation, rewarding student actions by semantic agreement with sampled teacher actions, so teacher token probabilities and shared tokenization are no longer required. It costs an on-policy RL training loop with sampling from both student and teacher at each state, which is substantially more compute- and orchestration-intensive than offline supervised fine-tuning, though the teacher can be a black-box API. It can fail if the sampled teacher actions are unrepresentative or the semantic-agreement reward is noisy, and the gains are demonstrated only on curated tool-use tasks, so transfer to other agent workloads is unverified.
