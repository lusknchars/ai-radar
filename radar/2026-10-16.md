#### 1. Open-privilege measurement for agent security defenses

Ajar replaces the two-axis evaluation of agent defenses (attack success and benign utility) with a third axis that directly measures privilege left open, by injecting unneeded candidate tool calls into existing benchmarks such as AgentDojo. It costs benchmark instrumentation per task and additional evaluation runs on top of the benchmark the team already uses, plus engineering to generate valid-but-unnecessary tool calls from tool schemas and reference solutions. It can fail if the generated candidate calls do not reflect realistic privilege escalation in the team's actual tool surface, or if a defense appears tight only because it over-refuses legitimate calls, a trade-off the metric exposes but does not resolve.

#### 2. Recursive LLM-invoke primitive replacing agent harnesses

Replaces specialized external systems such as memory frameworks (Letta/MemGPT) and self-improvement harnesses (ACE) with a single recursive code-mode LLM primitive, invoke, plus built-in constraint and monitoring hooks, eliminating manually designed tools and external memory or file systems. Costs are low in engineering complexity but shift burden to prompt design and API token spend, since all history lives as variables in a code environment; reported results run at roughly half the cost of Letta while scoring 8 points higher. Failure modes include unbounded growth of interaction history in the code environment on very long horizons, reliance on the LLM's code-generation reliability for recursive calls, and evaluation limited to two benchmarks, so gains may not transfer to other workloads.

#### 3. Multi-agent automated SFT data curation

It replaces manual SFT data engineering (adjusting proportions, pruning, repairing, and synthesizing rows) with a meta agent that separates execution from analysis, gathers proposals from independent subagents, and calls a synthesis subagent for gaps in the data pool. The cost is a multi-round loop in which the base model is retrained from scratch each round, plus orchestration complexity and API or GPU spend per iteration; a single 24 GB GPU constrains how large the retrained model can be. It can fail through context overflow in the agent loop, subagent proposals that do not transfer to held-out benchmarks, and compute cost scaling with rounds without guaranteed convergence.

#### 1. Uncertainty-driven weak-to-strong model escalation

The method replaces always-on frontier-model execution (or random/heuristic escalation) with a router that runs a cheap weak agent by default and escalates to a strong model only when the weak model's hidden states resemble past failed trajectories, plus a shadow observer that monitors the black-box strong agent after handoff. It costs maintaining a bank of successful and failed trajectory activations, per-step hidden-state comparisons, and the engineering complexity of a three-layer routing pipeline, though the estimator reuses existing activations so no extra forward pass or monitor training is needed. It can fail if the weak model's latent uncertainty is miscalibrated for a new task distribution, if logged trajectories do not cover the deployment domain, or if the strong agent's errors are not detectable from black-box outputs alone.

#### 2. Intrinsic fact-evolution benchmark for agent memory

Replaces downstream QA accuracy as the sole proxy for agent memory quality with direct inspection of the memory store against known fact-evolution trajectories (FEB-30), generated synthetically with deterministic ground truth. Costs are modest: it is an evaluation methodology requiring integration with the target memory system's store inspection, not a model or infrastructure change, and fits constrained infrastructure. It can fail to transfer because 30 synthetic trajectories across 6 categories may not represent a production workload's fact distributions, and results obtained on one representative memory system may not generalize to other architectures.

#### 3. Trained multi-turn LLM auditors for policy-compliance probing

Replaces manual red-teaming and zero-shot adversarial prompting of tool-using agents with a trained LLM auditor that conducts multi-turn, tool-mediated dialogues to surface policy violations, optimized via GRPO, DPO, or GFlowNet objectives against a composite reward. Costs include training the auditor (reinforcement-style fine-tuning of an LLM, feasible at small scale on a single 24 GB GPU only for small auditor models), designing per-policy reward components, and maintaining a simulated user environment with tool access. It can fail through reward hacking by the auditor, implausible user behavior that does not transfer to real traffic, policies whose violations only manifest in downstream systems the simulator does not model, and an auditor that overfits to the current agent version and must be retrained as the agent evolves.

Absolute performance remains low (F1 0.259), the method depends on a mature review history such as the Linux kernel's, and it can fail on projects with sparse or unstructured review discussions or where retrieved precedents are stale or inapplicable. (agentes_de_codigo · testar) arxiv.org/abs/2610.21925
- **Versioned temporal memory with labeled fact history** — TEM replaces flat RAG or overwrite-style memory with versioned, source-linked fact records whose historical entries are explicitly labeled before generation. It costs an extraction and storage pipeline for versioned records plus event memory, but it is training-free and reduces evidence to 94-118 tokens per answer, lowering inference cost. It can fail if fact extraction misses or mislinks updates, if version ordering or labeling is wrong, and its gains are demonstrated only on two conversational benchmarks, so performance on other domains is unverified. (memoria_e_contexto · testar) arxiv.org/abs/2610.21900
- **Recursive self-improvement with evolving meta-agent orchestration** — RSIFlow replaces fixed, hand-designed self-improvement loops with a meta-agent that diagnoses bottlenecks from trajectories and dynamically selects component-specific improvement workflows, distilling outcomes into reusable skills. It costs substantial additional LLM calls for diagnosis, workflow selection, and meta-agent harness evolution, increasing per-task token spend, latency, and orchestration complexity relative to single-pass agent runs. After adoption it can fail through compounding errors if the meta-agent distills spurious lessons from noisy feedback, through evaluation-benchmark overfitting, and through unbounded recursive refinement that inflates API cost without proportional quality gain. (orquestracao_multiagente · testar) arxiv.org/abs/2610.21791
- **Domain-native CAD agent harness with SFT and online RL** — Replaces a general-purpose coding harness for CAD agents with a domain-native harness exposing semantic CAD actions, decision-oriented observations, and persistent state, plus a pipeline of trajectory-derived SFT and geometry-grounded online RL. Costs include building and maintaining a CAD-specific action/observation layer, collecting interaction trajectories, and running SFT plus online RL against a geometry evaluation environment, which is a substantial engineering and compute commitment beyond inference-time prompting. The approach can fail if the harness's semantic action set does not cover the target CAD operations, if trajectory supervision encodes suboptimal decisions, or if the learned policy overfits to the benchmark procedures and does not transfer to other CAD tools or workflows. (planejamento_e_decomposicao · observar) arxiv.org/abs/2610.21755
- **LLM-agent simulation of endogenous delegation and polycentric governance** — The method replaces purely analytical game-theoretic analysis of delegation with 30-agent LLM simulations used to probe emergent institutional structures. It costs API calls across matched simulation pairs plus a repeated-game orchestration harness, and provides no efficiency, latency, or quality improvement for production inference workloads. Its findings are descriptive rather than prescriptive: observed cycles of concentration, exploitation, and exit depend on prompt design and model choice, and the cross-model behavioral difference (Sol versus Luna) may not replicate across other models or scales. (orquestracao_multiagente · nao_aplica) arxiv.org/abs/2610.21746
- **Intervention-label steering to localize and fix agent failures** — The method replaces discarding or replaying human interventions as training data by using them as labels to learn a causal steering direction at a specific residual-stream depth, optionally consolidated into weights via LoRA. It costs an interpretability pipeline (rule-based overseer, probes, direction learning, dose/site selection on training data) and per-model validation effort; the narrow results cover only one failure type on models up to 12B parameters. It can fail because outcomes vary by model family: LoRA consolidation succeeds on one model but breaks retention on three others, the pre-registered geometric predictor failed two out-of-family tests, and prompt-based instruction actively worsened behavior. (recuperacao_de_falha · observar) arxiv.org/abs/2610.21708
