#### 1. Serving-stack-aware tool-call evaluation protocol

The technique replaces naive tool-call fidelity measurement, which treats serving-stack rejections and parse failures as model errors, with a protocol that logs structured failure metadata, probes per-model serving behavior (Ollama template flags, llama.cpp, vLLM, SGLang), and reports per-instance rather than turn-pooled estimates. #### 2. Failure-guided growth of reusable agent harness code

The method replaces per-task in-context reconstruction of control logic with a shared executable harness that is iteratively grown from failure traces, reserving LLM calls for task-specific reasoning. It costs an offline optimization loop with function-level tracing, joint failure repair, and gated rollback, plus ongoing maintenance of an accumulating code artifact whose complexity grows with use. After adoption it can fail when repairs overfit to the training task distribution, when the success gate misses regressions not covered by held-out tasks, or when task drift makes the frozen control code obsolete.

#### 3. FlyHash locality-sensitive hashing for agent memory retrieval

FlyHash replaces dense-vector embedding stores searched with ANN indexes such as HNSW (and conventional SimHash binary codes) with sparse random-projection plus winner-take-all binary codes for agent memory retrieval. Its cost is practical rather than accuracy-related: at equal bits its codes are larger and slower to compare than SimHash's, and HNSW dominates both hash methods at ordinary scale, with a sparse-set comparison recovering only part of the latency gap. It can fail to deliver any deployment benefit unless the workload is genuinely bit-budget-constrained, since the quality-per-bit advantage does not translate into memory or latency savings against the current default.

It can fail outside controlled benchmarks: reported gains come from Cybench, CVE-Bench, and ExploitGym, ablations show each component matters (so partial adoption may underperform), and the approach depends on specific open-weight models whose availability and behavior may change. (orquestracao_multiagente · observar) arxiv.org/abs/2611.04196
- **Execution-grounded completion contracts via independent control plane** — The technique replaces the LLM agent's self-reported task completion with an independent control plane that observes a deadline-bound service-state predicate, admits or rejects completion, and directs recovery. It costs an additional control-plane component, state-predicate instrumentation per service, and deadline monitoring that can delay or reject legitimately completed work when observation lags. It can fail when state predicates are mis-specified, when observability of the target service is itself delayed or incomplete, or when healthy tasks are terminated as unverified due to monitoring faults rather than task faults. (recuperacao_de_falha · testar) arxiv.org/abs/2611.04182
- **Cross-domain benchmark for scientific 3D VQA agents** — This is a 250-question expert-reviewed benchmark that replaces ad hoc, discipline-specific 3D evaluation protocols with a unified VQA harness supporting native 3D artifacts, MCP-based inspection tools, and rendered 2D baselines. It costs nothing to deploy as a model, but adopting its findings implies building agentic file/code-execution and MCP tooling pipelines, which adds integration complexity. Results can fail to transfer because the benchmark is small (50 questions per domain), models score at most 0.53, and tool-access harnesses may not match a given production stack. (avaliacao_de_agente · observar) arxiv.org/abs/2611.04087
- **Agent-synthesized wiki procedural memory from execution traces** — WASP-Mem replaces static, hand-built agent harnesses and prescriptive memory schemas with wiki pages that the agent itself distills from execution traces and feedback, consolidating reusable actions and recovery strategies without any model training. The cost is ongoing trace ingestion and synthesis via LLM calls (third-party APIs are sufficient), plus the key operational investment: human diagnosis of failed traces, which the paper shows is what drives sustained gains. It can fail when no human diagnosis capacity exists (self-judgment refinement is markedly weaker), when the target procedures lack repeated trace volume to consolidate, and because results are validated on a single benchmark and may not transfer to proprietary enterprise workflows. (memoria_e_contexto · testar) arxiv.org/abs/2611.04003
- **Looped latent-recurrent transformer with elastic depth** — Replaces fixed-depth inference and the need to deploy larger checkpoints with a single 4B checkpoint whose shared recurrent block is applied a variable number of times, trading extra latent compute for accuracy instead of longer outputs or bigger models. Costs additional latency and compute per generated token roughly proportional to loop count, requires inference-stack support for looped execution (non-standard serving code), and the reported gains stem from a 6-trillion-token pre-training run plus NVFP4 training and RLVR post-training that the reader cannot replicate. Loop benefits are benchmark- and task-dependent (largest on coding, agentic, long-context), may not transfer to the reader's workload, and tooling for last-loop-only KV caching and difficulty-aware loop routing may be immature outside the authors' release. (arquitetura_eficiente · testar) arxiv.org/abs/2611.03998
- **Model-specific alignment drift measurement for LLM agents** — The method replaces the assumption that an LLM agent's behavior is fully determined by its prompt with a fixed psychometric instrument that quantifies stance across repeated discussion rounds, independent of any dynamics model. It costs repeated multi-round agent conversations plus per-round instrument scoring across candidate models, which is feasible on third-party APIs but adds evaluation latency and token spend before any simulation is trusted. It can fail because findings are model-specific and may not transfer across model versions, issues, or population sizes, so a model validated today can drift differently after a provider update. (avaliacao_de_agente · testar) arxiv.org/abs/2611.03980
