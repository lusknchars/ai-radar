The paper replaces passive or single-pass action-review monitors with hardened blocking monitors whose weaknesses were found by tasking adversarial agents with evading them, and it details concrete design fixes (broader tool coverage, transcript formatting, an agentic monitor stage). #### 2. On-policy residual learning for diffusion language models

ORL replaces standard multi-step DLM denoising (and, in single-request serving, autoregressive decoding with speculative decoding such as EAGLE3/DFlash) by carrying residual predictive distributions across denoising steps and training on-policy with an entropy-contraction objective, served via the dlmrt engine. It costs a residual-learning fine-tuning run (36 H100-hours and 4.2M self-generated tokens on LLaDA-2.1-mini, feasible on a modest budget), dependence on a custom engine, and added system complexity in residual capture, block-diffusion attention, and packed training. It can fail because results are demonstrated on a small set of converted or existing DLMs, the Pareto gains are shown mainly for single-request serving rather than batched production traffic, and quality parity may not hold on task distributions outside the reported benchmarks.

#### 3. Judge-guided tree search for agent self-modification

The method replaces the practice of re-running benchmark subsets to score every candidate self-modification of a coding agent with an LLM-as-a-judge pairwise comparison signal aggregated via a regularized Bradley-Terry model, reserving full task evaluations only for the most promising tree-search nodes. The cost is the added judge-model API calls and implementation complexity of a disaggregated tree search with rank-based parent sampling, though total reported resource use is lower than prior frameworks. What can fail: the judge's pairwise rankings may not correlate with true downstream task performance on a different codebase or task distribution, silently steering search toward patches the judge favors rather than patches that work, and gains are demonstrated only on the Polyglot benchmark with no reported replication.

- **Trajectory-aware trie retrieval of tool subsets** — It replaces exposing the full tool registry in the prompt with a retrieval front-end that indexes observed tool-call sequences in a trie and ranks a small candidate subset using a learned blend of empirical and contextual priors. It costs building and maintaining the trajectory index and the blending model, plus a retrieval step per turn, and its benefit depends on having logged tool-call sequences representative of production usage. It can fail when production trajectories diverge from indexed ones (cold-start or novel workflows), where pruning the registry to five tools may omit the correct tool, and the paper notes three model-environment pairs where accuracy trails full-registry selection by up to 2.2 points. (uso_de_ferramenta · testar) arxiv.org/abs/2610.21267
- **Tool-equipped LLM agent over video-clinical hierarchy** — TRACER replaces task-specific model training on protected health data with a training-free pipeline that builds minute-level action records from video, aggregates them with clinical records into hourly reports, and lets an LLM agent query this hierarchy through tools. The cost is a multi-stage perception and summarization stack plus repeated vision and LLM inference over long video (hundreds of hours per patient), which on a single 24 GB GPU or API budget means substantial preprocessing latency and inference spend. It can fail through error propagation from imperfect action detection into downstream reports and answers, dependence on backbone quality, and evaluation limited to two ICU patients for QA, so accuracy may not transfer to other wards or hospitals. (uso_de_ferramenta · observar) arxiv.org/abs/2610.21266
- **Autonomous agent onboarding via supervisor coding agent** — AutoOnboarder replaces manual prompt engineering, model selection, and harness tuning for LLM agents with an autonomous supervisor coding agent that iteratively edits the foundation model choice, prompt, and harness source code using only tens of task examples, with evaluation data isolated on a separate VM. It costs the compute and API spend of running an iterative Onboarder-agent loop on a sandboxed environment, plus the engineering effort to build a robust environment with a structured thought interface, controlled internet access, and a broad model search space. Onboarding outcomes are highly variable and the resulting agents remain imperfect, so a production deployment can inherit silent failures if the small onboarding example set does not represent real workload distribution.
