#### 1. Idempotency-key guard on agent tool writes

The technique replaces blind retry or model-level caution when a tool write times out or errors: a small harness guard that attaches an idempotency key to every write, letting the service deduplicate redeliveries. Cost is modest engineering (a key-generation and propagation guard, plus tool contracts that accept keys) with no model, GPU, or serving overhead; where contracts cannot accept keys, only waiting with a known in-flight bound partially substitutes. It fails when tool APIs do not support idempotency keys, when faults occur outside the service boundary the guard covers, and agents still misreport success (90% of duplicated episodes were reported as successful), so ledger-level auditing remains necessary.

#### 2. Privileged Self-Practice: PI in sampler, not loss

PSP replaces on-policy self-distillation, in which token-level supervision from a privileged-information teacher causes the student to act confidently without the underlying information, with a sampler-side intervention: an analyzer model writes a short per-task instruction when rollouts mostly fail, the task is resampled with that instruction in context, and training proceeds with an unchanged GRPO objective. The cost is an additional analyzer model and a second sampling pass per failing task, plus the existing infrastructure for GRPO-based RL post-training on multi-turn agent benchmarks. It can fail if the analyzer's instructions are inaccurate or unhelpful, if the workload lacks a clear failure signal to trigger instruction injection, or if the team's pipeline cannot support on-policy RL rollouts within a 24 GB GPU budget without API-based student models.

#### 3. Cross-architecture post-training quantization of TTS with staged ablation and per-layer GPTQ

The method replaces full-precision TTS weights with 4-bit per-channel quantization, using a staged ablation to locate the model-specific sensitive component and per-layer GPTQ to repair it. The cost is a quantization and validation pipeline per model and target runtime: outcomes at the same bit width vary by architecture (2.8 UTMOS loss on Supertonic versus 0.07 on Kokoro), so no single recipe transfers. What can fail is quality collapse from per-tensor scaling even at 8 bits, misidentified sensitive layers when skipping the ablation, and kernels that are slower than fp32 on a given runtime despite lower bit width.

#### 1. Training-free contrastive decoding with small steering model

Replaces per-model training for CoT compression, steering-vector methods, and heuristic early stopping by adding a scaled logit difference from a small model run twice (brief-prompted vs verbose-prompted) to the large model's logits at every decoding step. Costs two extra small-model forward passes per generated token plus per-step logit manipulation, which roughly triples inference compute per token even though total tokens fall, so net latency and cost savings depend on the small model being much cheaper than the large one. Can fail if the steering strength is mis-tuned (accuracy degradation on tasks needing extended verification), if no suitable smaller reasoning model in the same family is available, or on workloads where the claimed accuracy parity does not transfer.

#### 2. Hybrid latent-text reasoning with tool integration

Replaces purely text-based chain-of-thought and tool interaction in LLM agents with a unified generation process that alternates between latent reasoning (via a HybridLink module and continuous working memory) and text-based tool calls, reducing tokens and latency. Costs include training the HybridLink plus two post-training stages (HybridSFT and HybridRL), added architectural complexity over standard prompting or ReAct-style loops, and dependence on a custom serving path rather than off-the-shelf API inference. Failure modes include coordination errors at latent-text transition points, degraded interpretability if latent thoughts are inspected only superficially, and results that may not transfer when applied to backbones or tool schemas different from those used in the paper's training.

What can fail: reported gains do not transfer to unseen problems, are explained by overfitting or transferring existing behavior rather than using privileged information, and so the approach may deliver no out-of-distribution improvement in production. (destilacao · observar) arxiv.org/abs/2610.18613
- **Paired factual probes to diagnose agent action errors** — The method replaces uninterpretable single-pass action scoring with behavioral diagnostics: each next-action decision is paired with independent factual probes about the same state, separating perception failures from decision failures and enabling a repair path where the model's own correct factual answers are composed by code to fix the action. It costs additional probe queries per decision state, benchmark construction effort, and code to compose answers, adding latency and engineering complexity to the evaluation loop. It can fail when the diagnosis relies on synthetic probes that do not transfer to production states, and the abstract notes that on real states the missing element is often the next sub-goal, which factual probing and code composition may not supply. (avaliacao_de_agente · testar) arxiv.org/abs/2610.18579
- **Explicit skill preselection over implicit routing** — Explicit preselection of relevant skills before agent execution replaces implicit routing, in which the agent scans full skill metadata and decides what to load during the task. It costs an additional selection step with its own latency and coverage trade-offs, and requires a mechanism (retriever or selector model) to pick candidate skills from the library. It can fail when the preselector misses the golden skill, since the agent then has no opportunity to recover it, and gains shrink when libraries are small enough that implicit routing has not yet collapsed. (uso_de_ferramenta · adotar) arxiv.org/abs/2610.18522
- **Domain-specific coding-agent harness with task skills and verification loop** — The technique replaces a generic coding-agent harness (and reliance on frontier proprietary models) with a domain-specific harness that adds task skills and a verification loop for long-document-to-structured-output tasks. The cost is engineering effort to build domain skills and verifiers, plus extra verification passes that increase token consumption and latency, and the reported gains are measured only on clinical trial protocol digitization. After adoption, agents can still fail in the transcription and structuring stage, so structured outputs require downstream validation, and the skill assets may not transfer to other document domains without rework. (agentes_de_codigo · testar) arxiv.org/abs/2610.18507
- **Derived-reference generation for tool-call judges** — DeRef replaces giving the judge raw (possibly truncated or reference-free) conversation history by having a separate model read the full history without seeing the candidate argument and write an explicit reference stating what the value should be. It costs one additional model inference per judged argument, adding latency, API or GPU cost, and a new pipeline component. It can fail when the reference-writing model itself misderives the intended value, since judges are shown to follow the visible reference even when it is incorrect, so a wrong reference can systematically flip verdicts. (avaliacao_de_agente · testar) arxiv.org/abs/2610.18497
- **Selective teacher-guided RL for tool use** — The method replaces pure reinforcement learning and direct teacher supervision (SFT/distillation) for training small language models to use external tools, combining reverse-KL token-level teacher feedback on low-reward trajectories with forward-KL demonstration supervision. It costs a capable teacher model accessible during training, RL training infrastructure, and added implementation complexity over plain SFT or distillation. Adoption can fail if the teacher's tool-use preferences contain errors that persist through forward-KL supervision, if the reader lacks RL training capacity on a single 24 GB GPU, or if results on BFCL v4 and API-Bank do not transfer to the reader's specific tool schemas and APIs. (uso_de_ferramenta · observar) arxiv.org/abs/2610.18459
- **Agentic spatial search for city-scale 3D grounding** — Urbex replaces candidate-ranking pipelines that depend on precomputed 3D instance proposals with a VLM agent that actively navigates a multi-view city scene (querying landmarks, zooming, rendering oblique views) before committing a bounding box, trained with reinforcement learning on CityRefer. The cost is an interactive multi-view rendering environment, RL training of the tool-use policy with localization and shaping rewards, and a VLM agent capable of sequential spatial reasoning, none of which is off-the-shelf for a constrained-infrastructure team. Failure modes include the agent committing to a wrong region during search, degraded performance on scenes whose geometry or landmark distribution differs from CityRefer, and environment/rendering engineering overhead that may exceed the cost of a simpler ranking baseline for smaller scenes. (uso_de_ferramenta · observar) arxiv.org/abs/2610.18356
- **Planner-executor harness for long-horizon robot manipulation** — Orchestra replaces monolithic end-to-end action policies for multi-step robot instructions with a harness that decomposes instructions into ordered subtasks, maintains shared spatial and progress context, and uses a separately trained progress evaluator to decide when to advance. The cost is added system complexity: a planner, context tracking, and a separately trained progress evaluator on top of the action policy, plus dependence on the underlying pi_0.5-style policy. It can fail when the progress evaluator misjudges subtask completion, when object-location tracking drifts as the scene changes, or when the base action policy cannot execute a decomposed subtask it was not trained on. (planejamento_e_decomposicao · observar) arxiv.org/abs/2610.18352
- **Interview-enriched LLM user simulation for CRS evaluation** — SimInter replaces user simulators conditioned only on ratings, demographics, and static profiles by enriching profiles through synthetic LLM interviews grounded in historical conversational evidence, with a turn-level audit agent flagging fabrication and stereotyping. The cost is additional LLM inference for interview generation and auditing per simulated user, plus pipeline complexity; it is feasible on API access or a single GPU, but the paper validates only movie recommendation on ReDial, so transfer to other domains is unverified. After adoption, the main failure mode is residual fabricated or stereotyped attributes passing the audit (about 5.7% of claims unsupported and 4.8% auditor disagreement), which can bias downstream recommender evaluation. (avaliacao_de_agente · testar) arxiv.org/abs/2610.18308
