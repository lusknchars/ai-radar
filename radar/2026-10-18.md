#### 1. Closed-world tool-call resolver before gating

The resolver replaces nothing in the existing pipeline; it adds a training-free pre-gate check (tool registry membership plus argument signature validation) that rejects calls to nonexistent tools or with undeclared arguments before any causal or security gate runs, since a hallucinated call is by construction outside what a gate decided. Its cost is negligible compute and latency (a lookup and a schema check), with the engineering burden of maintaining an accurate, versioned tool registry and correctly handling merged MCP namespaces where name collisions and shadowing create surfaces a single registry cannot express. It fails on the one irreducible residue: calls to real tools with borrowed arguments that are schema-indistinguishable from valid calls, which requires downstream gating or execution checks rather than closed-world resolution.

#### 2. Multi-agent auto-formalization with verified Dafny IR

MAGS replaces fuzz testing, static analysis, and LLM-as-a-Verifier for safety assurance of agent-generated code by translating programs into Dafny, repairing them against verifier feedback, and compiling verified code back to executables. The cost is a multi-agent LLM pipeline plus the Dafny toolchain, human-audited frozen API specifications, and repair-loop latency on every generated artifact. It can fail silently when the auto-formalized specification itself does not capture the intended target behavior, in which case the guarantee is vacuously satisfied.

#### 3. Encode-aware disaggregated MLLM serving with SM co-location

EAServe replaces naive disaggregated Encode-Prefill-Decode serving (or monolithic MLLM serving in vLLM/Dynamo) by treating the Encode stage as the control point for request admission, prefill placement, and GPU sharing, with micro-batching, partial prefill offload onto the encode GPU, and dynamic SM partitioning plus a TPE-based configuration search. The cost is substantial engineering complexity: it requires a multi-GPU disaggregated deployment, per-stage capacity profiling, SM-level partitioning support, and a Bayesian auto-selection layer, none of which maps onto a single 24 GB GPU or API-only setup. It can fail when workload modality mix or load shifts invalidate the profiled configuration, when SM co-location introduces interference that violates SLOs, or when the operator lacks the multi-GPU infrastructure the method presupposes.

#### 2. IDF-weighted inverted index for agent retrieval

SSR replaces passing the entire agent registry into the LLM orchestrator's prompt with deterministic, training-free lexical retrieval over Agent Card capability fields, using IDF weighting and an inverted index to score only a small candidate subset. It costs little in infrastructure since it requires no model training or embeddings infrastructure, but it adds an indexing component to maintain and its lexical matching can miss semantic relevance that embedding-based retrieval would capture. After adoption it can fail when agent capabilities are described with vocabulary disjoint from query terms, when the registry is small enough that full-catalog prompting was already tractable, or when synthetic-benchmark gains do not transfer to real heterogeneous agent descriptions.

Failure modes include reward hacking on execution-validated verifiers, imperfect mock-to-real transfer (48.1% success on the physical phone leaves most tasks failing), and evaluator-environment drift if the synthesis pipeline does not match real target apps. (avaliacao_de_agente · observar) arxiv.org/abs/2610.20939
- **Source-Judged Compaction (summary entry pruning)** — SJC replaces nothing architecturally: it is a training-free post-processing step layered on an existing compaction pipeline, scoring each summary entry for provenance in environment outputs or the prior summary and deleting unsourced entries, leaving the agent and compressor unchanged. Its cost is one additional inexpensive judge request per compaction event; the judge is a non-generative calibrated decision model, so no generative inference, fine-tuning, or extra context tokens are required. It can fail if the judge miscalibrates and prunes genuinely useful reasoning entries, and the reported gains are validated only on AppWorld and OfficeBench, so transfer to other agent workloads is unproven. (memoria_e_contexto · testar) arxiv.org/abs/2610.20927
- **Non-elitist evolutionary optimization of agent skills** — It replaces greedy, elitist skill refinement (keep only edits that immediately improve reward) with an evolutionary process that separately selects the version to deploy and lower-scoring versions worth further editing. The cost is additional execution and revision rollouts via API calls (task execution, revision proposal, and skill editing), plus infrastructure for versioned skill storage and comparative trace analysis. It can fail when evaluation tasks overlap with evolution tasks (the paper evaluates on the same instances, risking overfitting), when partial-repair lineages consume budget without converging, or when skills evolved on a weak model encode workarounds that mislead stronger models. (memoria_e_contexto · testar) arxiv.org/abs/2610.20926
- **Learned runtime inspection and repair for multi-agent executions** — Replaces post-hoc diagnosis of completed multi-agent failures and repeated re-execution search with a compact learned model that intervenes on ongoing runs, trained on 3,953 execution-verified repair pairs derived from over 24,000 trajectories. Costs include assembling or reusing verified repair data, fine-tuning and hosting an additional inspector model, per-step inspection latency, and integration work requiring the MAS to expose trajectories and support continuation replacement. It can fail on failure modes unlike the training repairs, misjudge when to intervene and corrupt otherwise healthy runs, and its claimed generalization to unseen frameworks and host models may not hold for the reader's specific stack. (recuperacao_de_falha · testar) arxiv.org/abs/2610.20780
- **End-to-end indirect prompt injection benchmark (INFUSE)** — INFUSE replaces ad hoc or single-turn prompt-injection tests with a 40-task, 56-attack benchmark that evaluates injection across full long-horizon agent trajectories including shell, code, and remote-service surfaces. The cost is evaluation compute (thousands of trajectories) and, if the prompt-hardening mitigation is adopted, a model-dependent security-utility trade-off that can degrade benign task performance. It can fail to transfer if the team's agent tools, surfaces, or task domains differ from the benchmark's 40 tasks, and heuristic versus LLM-based judgment (15.4% vs 19.6% ASR) shows measurement itself is unstable. (seguranca_e_guardrails · testar) arxiv.org/abs/2610.20776
- **Hardened benchmark for code-optimizing agents** — HPCAgent-Bench replaces ad hoc, single-accelerator evaluations of code-optimizing agents with a hardened framework of 689 kernels, hidden fuzzed-input judging, and paired-run intervention metrics. Adopting it costs engineering effort to wrap submissions through its C ABI or Python interface and to run the harness, plus agent token spend, which the paper shows can grow up to 3.0x without corresponding speedup gains. It can fail to inform production decisions if the reader's workloads differ from its HPC- and ML-kernel mix, and its cost conclusions depend on the token weights chosen. (avaliacao_de_agente · testar) arxiv.org/abs/2610.20673
- **Transcript-based capability evaluation on saturated benchmarks** — The method replaces discarding saturated benchmarks and retraining or building new ones, instead extracting capability signal from existing solution transcripts via pairwise judging, absolute scoring, or feature-based prediction. It costs an LLM-as-judge pipeline (API calls or a locally served judge model) plus transcript collection and validation against held-out unsaturated items, adding evaluation complexity but no model-training expense. Predictive accuracy can degrade under distribution shift: the protocols underestimated the first reasoning models released in early 2025, so judgments from older saturated items may not generalize to models with qualitatively new behaviors. (avaliacao_de_agente · testar) arxiv.org/abs/2610.20667
