#### 1. Fault-injection evaluation of tool-using agent failure handling

The paper is a diagnostic benchmark, not a method; the production practice it argues for is replacing trust in well-formed tool outputs with explicit result validation and error-channel-independent checks in tool-using agents. The cost is added validation logic and extra verification calls per trajectory, since the paper shows a simple prompt line asking the agent to check results does not improve detection, so validation must be implemented in the harness rather than delegated to the model. What can fail is that silent faults (plausible wrong values, schema drift, corruption) still pass through undetected at high rates (detection only 58.8% versus 91.3% for explicit errors), reasoning-model variants do not help recovery, and stochastic run-to-run variation (only 63.3% identical end states on fault-free runs) limits how much any single-run safeguard can guarantee.

#### 2. LTLf contract-based guardrails for tool-calling agents

It replaces stochastic post-hoc LLM judges and per-call rule-based blockers with a single deterministic artifact: assume-guarantee contracts in finite-trace LTL, compiled to DFAs that gate tool calls online and evaluate recorded traces offline. The cost is engineering effort, not compute: someone must formalize checkable predicates over tool calls and author and maintain a correct contract library per task domain, plus DFA compilation overhead. It can fail when contracts are incomplete, wrongly specified, or the predicate set cannot observe the relevant state, in which case harmful actions pass deterministically or benign ones are blocked, and coverage does not transfer across domains without rewriting contracts.

#### 3. Git-based shared research memory for agent collectives

Agora replaces independent, memoryless autonomous research agent sessions with an append-only Git DAG where every claim, hypothesis, and verification is an immutable, re-runnable commit, plus a derived index and diversity-aware selection to prevent monoculture. It costs only Git infrastructure and the agent compute itself (13 LM workers for 12 days in the reported run), but adds the complexity of maintaining the commit schema, index, and selection rule, plus occasional human intervention to break monocultures. It can fail through unverified or duplicated claims accumulating in the graph, collapse of the community onto one branch absent the diversity mechanism, and the absence of evidence that it beats simply running more independent agents on the same budget.

#### 1. Distilling SOP agents into code-based workflows

Replaces per-step LLM planning in repetitive SOP execution with a code-based workflow whose routing conditions are distilled from logged agent reasoning, so the LLM is no longer called to select each step. Costs a modest drop in completion (93.8% vs 96.8% in production, 75.8% vs 80.6% on tau2-Bench) plus a one-time pipeline of log collection, rule extraction, workflow compilation, and repair rounds on labeled failures. Can fail on out-of-distribution inputs not covered by logged runs, on SOPs that change and invalidate the extracted rules, and when the available training runs are too few or unrepresentative for the repair loop to close the accuracy gap.

#### 2. Scientific programming agent for drug discovery

DrugCoding replaces manually orchestrated drug discovery workflows with an LLM agent that plans tasks, routes to specialized scientific models, generates and executes code, and coordinates multi-agent validation. It costs the overhead of maintaining tool interfaces, model routing infrastructure, and multi-agent execution on top of API or local model usage, plus benchmark-specific adaptation. It can fail when scientific tools are misinvoked, when generated code executes incorrectly despite validation, or when the underlying LLM's planning or routing degrades on workflows outside the benchmark distribution.

#### 3. Clipped log-ratio graded scoring for agent benchmarks

Replaces binary pass/fail benchmark aggregation with a clipped log-ratio score against dated human or reference anchors, treating cost as a separate reporting axis. Cost is negligible: it is a re-scoring of existing run artifacts plus anchor selection, requiring no model changes or extra GPU work. It can fail if anchors become stale, if the clipped log-ratio metric is gamed on saturated tasks, or if graded credit masks regressions that pass/fail would surface.
