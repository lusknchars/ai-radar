#### 2. Direct KV cache drop and reposition operations for agents

It replaces context-engineering approaches (trimming or summarizing history, which invalidates the prefix and forces re-prefill) with direct KV cache operations, drop and repos, that control active cache without altering the trajectory. The cost is operational: you must run or integrate the AKV serving engine to manage stateful cache reuse, eviction, and restoration, which excludes third-party API-only deployments and adds a serving-layer dependency. Failure modes include incorrect cache reuse from history dependence (identical token sequences with different cache states), potential accuracy loss if aggressive drop policies remove needed context, and policy fragility since gains depend on the workload-specific drop policy.

#### 3. Automated harness optimization for multi-reference image generation

The method replaces hand-written orchestration harnesses (reference processing, generation, diagnosis, and selection logic) with harness code iteratively rewritten by a coding agent while the generator and reasoning models stay frozen. It costs additional inference overhead from tool-augmented reasoning (partially controlled via learned local tool-call chains), plus the engineering complexity of maintaining an evolving skill and tool library around an API-based MLLM. It can fail if the self-improvement loop overfits to the evaluation distribution, if evolved tools are unreliable or unsafe to execute, and the reported gains are validated only on two chart benchmarks with a single proprietary base model. - **Multi-model shared agent harness optimization** — MaD-RSI replaces single-model recursive self-improvement of agent harnesses, in which a harness is overfit to one LLM and must be re-optimized per model, with joint optimization of one shared harness using failure trajectories from several heterogeneous LLMs. The cost is a more complex training pipeline that must run and collect trajectories from multiple models during optimization, plus API or inference spend for each participating model, which is non-trivial even if lower than per-model re-optimization. It can fail if the shared harness converges to an average that underperforms a model-specific harness on the reader's actual production model, if the reader only uses one or two models (removing the diversity signal the method depends on), or if trajectory collection across API providers is rate-limited or expensive. (uso_de_ferramenta · observar) arxiv.org/abs/2610.28201
- **Mining business rules into executable agent test specifications** — AgenTest replaces manual business-rule test writing and success-only or policy-based agent evaluation with automatic mining of system prompts, tool definitions, and domain knowledge into Given-When-Then specifications, each exercised via multi-turn interactions and a hybrid oracle over messages, tool calls, and state. The cost is the engineering to build satisfying environment states and simulated users per specification, plus LLM and orchestration expense for multi-turn test execution; the paper shows no turnkey tool, so adoption means reimplementing the pipeline. It can fail where rules remain implicit and unmined, where environment instantiation is infeasible for real production systems, or where the hybrid oracle misjudges ambiguous traces, producing false positives or missed violations. Costs harness engineering effort and metadata bookkeeping on every memory operation, plus some added latency per check; no model retraining or extra GPU capacity is required. It can fail through mislabeled provenance at ingestion, incomplete coverage of an unmonitored channel, or an over-restrictive policy that blocks legitimate memory use, and the abstract provides no measured attack-reduction or overhead figures.
