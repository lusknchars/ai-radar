#### 1. Action chunking for LLM-driven control loops

ChunkAct replaces per-primitive LLM reasoning over full interaction history with offline-compiled chunks of chained primitives that execute autonomously and return control to the planner only on failure, making LLM cost scale with decisions rather than primitive count. The cost is an offline compilation step that converts the agent's memory into chunks, plus loss of per-step planner oversight, since execution becomes memory-free between decisions. It can fail when a sub-goal's routine does not match the compiled chunk, when failure detection within a chunk is unreliable, or when tasks require mid-primitive replanning that the chunk structure cannot express.

#### 2. Numerically stable KL divergence computation

The method replaces conventional closed-form KL formulas and PyTorch F.kl_div with stable decompositions, compensated arithmetic, and analytic gradients that avoid catastrophic cancellation when comparing nearby distributions. Cost is limited to integrating the released stablekl library and re-validating existing KL-dependent code; there is no additional memory, latency, or infrastructure requirement. What can fail is incomplete coverage if the reader uses KL variants outside the 18 repaired families, and existing models trained under the biased gradients may shift behavior once losses are corrected, requiring re-tuning of hyperparameters that were implicitly calibrated to the old errors.

#### 3. Hybrid latent-text reasoning with tool integration

Replaces purely text-based chain-of-thought and tool interaction in LLM agents with a unified generation process that alternates between latent reasoning (via a HybridLink module and continuous working memory) and text-based tool calls, reducing tokens and latency. Costs include training the HybridLink plus two post-training stages (HybridSFT and HybridRL), added architectural complexity over standard prompting or ReAct-style loops, and dependence on a custom serving path rather than off-the-shelf API inference. Failure modes include coordination errors at latent-text transition points, degraded interpretability if latent thoughts are inspected only superficially, and results that may not transfer when applied to backbones or tool schemas different from those used in the paper's training.

#### 2. Exact KV cache migration across LoRA updates

LiveLoRA replaces full-history re-prefill when updating a LoRA adapter for active sessions by migrating the final-block KV cache exactly, exploiting frozen lower decoder blocks and fixed K/V down-projections so that adapter, cache, and logits are committed together. It costs approximately 4.8% decoding overhead, imposes structural constraints on the model (frozen lower blocks and fixed K/V adapter projections across versions), and adds runtime complexity for candidate K/V reconstruction and reevaluation of the latest token. It can fail if the model or adapter setup violates these assumptions, if exact-arithmetic equivalence is broken by numerical or implementation divergence, or if the validated regime (a 3B model, 32 sessions, 8K-token histories) does not match the reader's production scale or model family.

#### 3. Externally injected uncertainty for error repair

This replaces self-verbalized stepwise confidence as the trigger for backtracking in agentic reasoning, which the paper shows fails as a monitoring signal, with external detection of error steps followed by injection of an explicit low-confidence token or rethinking instruction. The cost is an additional error-detection component (a verifier, separate model pass, or heuristic) plus extra generation for revised continuations, adding latency and API spend, and the self-monitoring prompting itself provides no usable signal. Injected doubt can cause the model to discard already-correct reasoning, reducing solve rates by up to 22.8 points, so the approach fails when the external detector produces false alarms on sound steps.

It fails if any component bypasses the canonical representation, if schemas are too permissive (e.g., extra fields a malicious server adds that the model fills with user data), or if non-JSON channels are added later without the same treatment. (seguranca_e_guardrails · adotar) arxiv.org/abs/2611.30624
- **LLM-mediated system-call interception for agent defense** — AgentBouncer replaces prompt- and trajectory-level defenses, which inspect only the initial prompt and tool-call sequence, with an LLM arbiter that mediates the actual system calls an agent triggers, gated by preseeded policy rules and hierarchy-aware caching. It costs about 47 seconds and USD 0.0036 per benign task, plus the engineering effort of integrating a syscall-interception layer into the agent's tool execution path. It can fail against attacks outside its evaluated four vectors, through arbiter misjudgment of necessity or safety on novel tasks, and if cache hits silently propagate an incorrect prior allow/deny decision. (seguranca_e_guardrails · testar) arxiv.org/abs/2611.30621
- **State-verified RL rewards for agent training** — State-Verified Reinforcement Learning replaces text-level LLM judges and isolated tool-call checks as the reward source for agent training, instead supervising GRPO with deterministic verification of workspace state transitions, workflow ordering, and side effects, gated by hard zero reward on critical violations. It costs an isolated sandbox per episode that snapshots state around every tool call, a deterministic verifier, 1,000 verifiable training instances, an evidence-grounded judge for saved artifacts, and full online RL training of a 27B model, all of which exceed constrained single-GPU infrastructure. After adoption it can fail when the verifier's notion of a critical violation is incomplete or mis-specified, since reward hacking shifts to whatever state properties the verifier does not audit, and gains may not transfer beyond the 11 educational categories and 16 native tools used for training. (treino_eficiente · observar) arxiv.org/abs/2611.30559
- **Rubric-based behavioral benchmark for coding agents** — sudo L7 replaces ad hoc or test-pass-only evaluation of coding agents with 60 staff-engineer-authored tasks graded against 1,287 hidden atomic rubric criteria spanning eight behavioral dimensions, including truthful reporting and risk flagging. Adopting it costs nothing in infrastructure since results are on a public leaderboard, but replicating the grading methodology internally requires an agentic grader that reads transcripts, runs code, and treats test output as evidence, which adds evaluation pipeline complexity. It can fail as a selection tool because tasks are built around prior frontier-model failures in mostly private codebases, so scores may not transfer to the reader's domain, and model grader agreement with humans is only 85-86%, leaving roughly one in seven criterion verdicts unreliable. (avaliacao_de_agente · testar) arxiv.org/abs/2611.30517
- **Automated LLM context engineering from experience** — Automated LLM-as-context-engineer (LCE) methods replace manual prompt and instruction engineering by having the LLM distill generalizable instructions or experiences from offline trial trajectories. Their cost is additional offline generation over trials plus longer engineered contexts at inference, adding latency and token spend. The paper shows these methods fail when failure modes in reasoning trajectories are diverse (gains correlate negatively with failure-mode diversity, r=-0.5), do not reliably beat chain-of-thought, and do not consistently improve with more parameters or iterations, so adopting them in production is not supported by this evidence. (memoria_e_contexto · nao_aplica) arxiv.org/abs/2611.30494
- **Empirical audit of agent-caused database damage and recovery** — The study replaces intuition about guard layers and model choice with a scripted mistake library (22 canonical errors) and engine-native recovery drills across 12 engines and permission/recovery arms, showing damage is governed mainly by engine permissions and undo capability rather than the model. It costs nothing to adopt as knowledge, but operationalizing it means enforcing least-privilege credentials, tested backups, and engine-specific recovery procedures rather than relying on a guard layer whose benefit was not consistently supported. Its conclusions can fail to transfer because the post-hoc analyses (S1-S13) are exploratory and uncorrected, the preregistered outcome and original-row loss disagree about the guard layer on four engines, and one hypothesis was uninformative because agents never found the credential. (recuperacao_de_falha · observar) arxiv.org/abs/2611.30483
