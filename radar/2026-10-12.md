#### 1. EvasionBench: benchmark for runtime-monitor evasion

This work does not replace a production method; it adds a 50-task benchmark for measuring whether LLM agents circumvent runtime monitors under ordinary task pressure, which can replace ad hoc or absent evaluation of monitor robustness. Running the benchmark costs only API or single-GPU inference budget plus engineering time to wire in one's own monitor and tool policies, since it requires no training. Findings can fail to transfer because evasion rates vary substantially across models, benchmark tasks may not match the reader's domain-specific policies, and results measured with best-of-3 sampling overstate single-attempt production risk.

#### 2. Coding agents synthesizing generalized TAMP policies

The method replaces hand-engineered TAMP planners and TAMP-specific engineering by having a coding agent (e.g., Claude Code, Codex) interactively synthesize a single frozen program that generalizes across problem instances. It costs a fixed up-front program-synthesis budget of agent API calls with simulator access, plus evaluation infrastructure; inference per instance is then cheap, about 10x less computation than the planner. It can fail on environments where success remains low (56% on the hardest), when held-out instances deviate from the regularities the program exploited, or when no reliable simulator is available for the agent to calibrate against.

#### 3. Entropy- and CKA-based layer selection for speculative decoding

The method replaces fixed, position-based heuristics for choosing which decoder layers feed the draft model in EAGLE-style speculative decoding with a data-driven selection based on matrix entropy (informativeness), CKA (diversity), and token-entropy filtering. The cost is a one-time offline analysis pass over calibration data plus added pipeline complexity; inference architecture and memory footprint are unchanged since only the layer subset used by the draft head differs. It can fail if the calibration distribution shifts, if the gains are small relative to the already-competitive default rule (which the paper itself concedes can remain competitive), or if the statistics are computed on too few or poorly filtered tokens.

#### 1. Role-isolated long-horizon program reproduction workflow

Program-Agent replaces a single monolithic coding-agent loop with a role-isolated workflow (analysis, implementation, review) plus revision management for compilation checks and failure recovery, which a small team can replicate as prompting/orchestration over API models; Program-Env replaces hand-built training environments with a feedback-driven pipeline that repairs sandbox builds and black-box tests. The agent-side cost is higher token consumption and latency from multi-role passes and exploratory analysis before implementation; the environment-side cost is substantial engineering and compute to build and verify 1,648 sandboxed repositories, which is not realistic on one 24 GB GPU. Failure modes include compounding errors across role handoffs, reference exploration that consumes context without improving the implementation, and environment/test suites whose black-box tests are too weak to verify correctness, so reproduced gains may not transfer to benchmarks other than ProgramBench.

#### 2. Held-out rubric benchmark for agent-building coding agents

AgentSWE replaces ad hoc acceptance of agent-generated agent code with commission-style evaluation: a frozen submission is tested on held-out cases graded against requirement-derived rubrics under pass/fail gates, rather than being judged by its behavior on the illustrative cases the builder saw. The cost is evaluation engineering effort: constructing held-out cases and rubrics per requirement, plus the API or GPU spend to run frozen submissions, and it measures rather than improves delivered quality. It can fail to transfer if the reader's tasks are narrower than the benchmark's 25 commissions, and rubric-based grading inherits the reliability limits of whatever grader is used.

#### 3. Rollout-time intervention for agentic RL

RTI replaces purely on-policy exploration in agentic RL by injecting reward-rubric evidence during rollout to convert failed trajectories into successful ones, then filtering interventions with excessive distributional shift before policy optimization. It costs additional rollout compute for intervention and filtering, requires well-specified evaluation rubrics per task, and adds off-policy correction logic to the training pipeline. It can fail when rubrics are unavailable or noisy, when filtering admits trajectories whose distribution shift destabilizes training, or when the resulting training still demands more GPU memory than a single 24 GB card provides for the chosen model size.
