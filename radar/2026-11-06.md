#### 1. Order-invariant typed-decision classification head (no generation)

Replaces generative multiple-choice or Likert/yes-no answering (prompting an LLM to emit an option) with a 182M-parameter scoring head that returns temperature-scaled probabilities per option plus an expected-error 'not sure' signal in one CPU forward pass for up to ten options. Costs: a fixed answer-type task format, an additional small model to host and calibrate, and quality below top leaderboard systems; calibration via temperature scaling degraded on held-out support questions (smooth ECE 0.027 to 0.045), so recalibration is needed per domain. Failure modes: Turkish-only scope, benchmark numbers contaminated by iterative test-set reading on guardrail, moderation, and customer-support tracks, and expected-error abstention that may not transfer to new question distributions.

#### 2. Pre-trained matrix-native transformer for zero-shot matrix completion

MatrixFormer replaces entry-by-entry imputation and per-task matrix completion pipelines (iterative imputers, low-rank factorization, tabular foundation models that repeat context per target) with one pre-trained transformer that emits a full predictive distribution for every missing entry in a single forward pass. Inference-only use fits a 24 GB GPU and avoids any training cost, but model size, licensing, and code availability are unstated, and the single-pass design still incurs transformer memory that grows with matrix dimensions. It can fail when real matrices violate the synthetic low-rank/latent-factor training assumptions, when missingness patterns fall outside the training distribution, or when zero-shot accuracy trails a task-specific model tuned on in-domain data.

#### 3. VAE with learned autoregressive latent prior

EVA replaces the standard-Gaussian prior constraint of a conventional VAE with autoregressive latent priors learned empirically from training data, implemented as a single additional linear layer. The cost is one extra linear layer plus the training of that prior, and inference claims faster sampling than autoregressive diffusion baselines without a stated magnitude. It can fail if the empirically learned prior does not close the prior-posterior gap on the reader's data distribution, and the claimed quality parity with diffusion baselines is validated only on image and sound benchmarks, not arbitrary domains.

- **Graph-based dual conversational memory** — Replaces flat conversational-history or generic RAG memory in repository-oriented assistants with a dual graph that links distilled conversation memories to code entities, using code-draft query grounding, graph expansion, and structure-aware compression. Costs include building and maintaining two graphs per session (entity extraction, embedding, cross-graph association updates), extra retrieval hops per turn, and implementation complexity beyond a standard vector-store pipeline. Failure modes include stale or incorrect entity-to-conversation links as the repository evolves, grounding failures when the generated code draft misidentifies the relevant entities, and retrieval noise from graph expansion that can exceed the compression gains. (memoria_e_contexto · testar) arxiv.org/abs/2611.07759
- **Empirical evaluation of third-party LLM API relays** — The paper replaces implicit trust in advertised model names and listed prices with repeated empirical testing of third-party API relays for answer fidelity, tool-permission compliance, and billing accuracy. It costs engineering time to run batch-matched comparisons, repeated sampling, and account-balance checks, but no extra model infrastructure. It can fail if a relay changes behavior over time, if screening misses injected or altered content, or if billing discrepancies remain hidden where balances and reference token counts are unavailable. (avaliacao_de_agente · adotar) arxiv.org/abs/2611.07650
- **Task-Tampering Indirect Prompt Injection Benchmark** — This benchmark replaces indirect prompt-injection evaluations that test planted instructions redirecting the agent toward an attacker-chosen task, instead defining attacks by unauthorized authority over decisions required by the benign task itself. It costs implementation effort to adapt the 90 validated cases across three tool-use environments to one's own agent architecture, plus inference costs for running evaluations across multiple models. After adoption, it can fail to surface vulnerabilities if the test cases do not cover the specific decision targets or tool schemas present in the production system, and defenses validated only on instruction-override benchmarks may appear more robust than they are against tampering attacks that manipulate values obtained during execution.
