The method replaces black-box text-based monitoring of agent transcripts (e.g., a strong LLM reading outputs) with white-box linear probes trained on internal activations, using the released FIBS dataset and a multi-layer, multi-token aggregation architecture. #### 2. Multi-reference test evaluation and peer-validated test generation

TestPrism replaces single-reference test evaluation with a joint criterion requiring generated tests to fail the initial state, accept all valid implementations, and reject all invalid ones; TestHelix replaces single-pass test generation with heterogeneous test-and-repair synthesis, peer cross-validation, and recursive self-improvement. The cost is the candidate-implementation suite needed for scoring and extra model calls for cross-validation and self-improvement loops, all feasible on API budgets but adding orchestration complexity. Adoption can fail because the recursive self-improvement loop can propagate faulty tests if peer validation shares the same model biases, and the benchmark's 300 Python-centric tasks may not transfer to the reader's languages or domains.

#### 3. Cross-model KV cache reuse with selective recomputation

Replaces full-context prefill by the target model whenever a session or cascade switches models: a small source model prefills once, its KV cache is linearly mapped to the target, and only the ~30-40% of tokens flagged by a rank-disagreement metric are recomputed by the target. Costs include holding both models' weights (or sequential loading), a calibration set to fit the linear maps and rank-disagreement statistics, and a residual 1-5% accuracy loss relative to native target prefill, plus engineering to integrate the mapped-cache path into the serving stack. It can fail when transfer error concentrates differently than the calibration data predicts, when the workload rarely switches or cascades models (making the prefill saving irrelevant), or when serving targets only fit on the GPU via APIs or aggressive quantization, where no open implementation of the mapped-cache path may exist.

#### 2. Experience-guided evidence-competition attacks on typed S1 models

S1-Evo replaces generic prompt-injection or override attacks with contract-aware perturbations of untrusted fields that compete with task evidence against typed S1 scorers, using offline margin-guided search and retrieval of 'experience cards' at test time. Cost is an offline seed-task optimization loop with re-verification plus a card store and retrieval step at inference; it adds no parameters to the production model but adds attack-side compute and pipeline complexity. It can fail when margin feedback is unavailable or coarse-grained, when retrieved cards do not transfer to unseen task distributions, and when deployed S1 interfaces add input sanitization or contract validation not modeled by the framework.

- **Tiered diagnostic benchmark for agent-trajectory auditing** — It replaces single overall-recall scoring and loosely generated trajectories with a six-tier diagnostic benchmark built mostly from real production trajectories, including benign lookalike cases and paired shortened or information-supplemented variants. It costs benchmark access plus the compute or API budget to run candidate auditors against it, and it provides no direct inference, memory, or quality improvement to a deployed agent. It can fail if its selected scenarios do not match the reader's deployment distribution, if teams tune auditors to the six tiers rather than to real risk coverage, or if the missed-risk patterns it exposes are not actionable within a small team's auditing stack. (avaliacao_de_agente · testar) arxiv.org/abs/2611.16493
- **Contained local evaluation harness for coding agents** — The kit replaces reliance on a single noisy hosted competition score and ad-hoc local testing with a local evaluator that sandboxes agent-written code in network-isolated containers, verifies conformance with the hosted scorer's prompts down to rendered tokens, and applies paired statistics that respect repository clustering. It costs container-orchestration infrastructure, maintenance of conformance checks as the hosted scorer evolves, and the compute to run hundreds of evaluations (about 250 runs per hour for a 4B agent on one high-end GPU), plus engineering effort to integrate one's own agent bundle. It can fail because the paper's own experiments show that screen-passing agent changes did not confirm on new tasks and that 65% of tasks were solved in none of eight baseline runs, so an adopted kit can still mislead if users underpower their comparisons or over-trust single-run gains. It costs multi-billion-token mid-training compute, a formal-verifier sandbox infrastructure, and trajectory-collection effort, none of which fit a single 24 GB GPU or a limited cloud budget. It can fail if the synthesized corpus or trajectories are not released, and its gains are demonstrated only for Lean theorem proving, with no evidence of transfer to general production workloads. It costs full RL training over a multi-role LLM pipeline: environment rollouts, reward infrastructure, and training capacity that exceed a single 24 GB GPU or API-only budget.
